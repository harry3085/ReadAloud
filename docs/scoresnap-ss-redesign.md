# ScoreSnap 전용앱(`/ss/`) 리디자인 작업 지시서

작성 2026-10-24 · 디자인 시안: claude.ai 디자인 캔버스 "ScoreSnap 전용앱 리디자인" (원장님 확인 완료)

## 0. 목표와 범위

- 대상: `public/ss/index.html`, `public/ss/scoresnap.js`, `public/ss/store.js`, `tools/scoresnap-worker/worker.js`
- **학원앱 쪽 ScoreSnap(`public/admin/js/scoresnap.js`)은 건드리지 않는다.** 전용앱만 바꾼다.
- 목표: 어두운 테마·이모지·작은 버튼·버튼 나열을 없애고, 학원앱 톤(밝은 회색 바탕 + 코랄)으로 통일한다. 폰은 **촬영**, PC는 **검토·수정·카톡 전송** 중심으로 흐름을 다시 짠다.
- **바꾸지 않는 것**: 채점 로직, 짝짓기, 서버 저장 스키마(`scoresnapSessions` 구조), `/api/scoresnap-grade`·`/api/ocr` fetch 가로채기(`index.html`의 `runJob`/`gradeViaPc`/`marksViaPc`), 마킹 좌표 계산(`_ssEnsureMarkPos*`, `_ssDrawMarks`). **화면(렌더)과 흐름만 바꾼다.**

## 1. 사용 패턴 (설계 전제)

- 폰: 정답지·답안지 **촬영**만 한다. 결과도 볼 수 있어야 하지만 주 작업은 아니다.
- PC: 결과 확인, ✓/✗ 수정, 이름 수정, 마킹 사진 확인, **카톡(PC 카톡)으로 학부모 전송** — 대부분의 작업이 여기서 일어난다.
- 채점은 학원 PC의 `worker.js`가 Claude Code로 **한 건씩 차례로** 처리한다(학생당 수십 초). 화면 문구도 이 사실에 맞춘다.

## 2. 디자인 기준

### 색·글꼴 (CSS 변수로 `index.html` `<style>`에 정의, scoresnap.js 인라인 색 제거)
```
--brand:#E8714A; --brand-dark:#D85A30; --brand-bg:#FEF2EC;
--bg:#f4f6f8; --surface:#fff; --text:#222; --sub:#5f6368; --border:#e0e0e0; --line:#eee;
--ok:#2e7d32; --ok-bg:#e8f5e9; --bad:#c62828; --bad-bg:#ffebee; --bad-bd:#f1b0b0;
--warn:#b45309; --warn-bg:#fff7e6; --warn-bd:#f5c26b;
font-family:'Noto Sans KR','Apple SD Gothic Neo',sans-serif;
```
- 회색 보조 글씨는 `--sub`(#5f6368)보다 연하게 쓰지 않는다(#888·#666·#777 금지 — 대비 부족).
- 점수 색: 80점 이상 `--ok`, 60~79 `--warn`, 60 미만 `--bad`.
- 사진 전체 화면 보기만 어두운 배경(#1c1d1f) 허용.

### 규칙
- 이모지 금지 → stroke SVG(Lucide 풍, `viewBox="0 0 24 24"`, `stroke-width="2"`, `currentColor`). 학원앱 `ICONS`/`iconSvg()` 패턴을 전용앱에도 만든다. 필요한 아이콘: camera, image, chevron-left/right, plus, more(⋯), x, check, refresh, copy, download, pen, maximize, monitor, file-check, minus.
- 터치 대상 최소 44px(폰). 주요 버튼 높이 52px, 둥글기 14px.
- **화면 하단 고정 액션바**: 그 화면의 주 동작 1개(코랄) + 보조 1~2개. 나머지는 ⋯ 메뉴로.
- 인라인 `style="..."` 덩어리 대신 CSS 클래스(`.ss-btn`, `.ss-btn--primary`, `.ss-card`, `.ss-row`, `.ss-chip`, `.ss-tabs` 등)를 만들어 쓴다.
- 기존 규칙 유지: 사용자 데이터는 `esc()`, `alert/confirm/prompt` 금지(`showConfirm`/`_ssToast`), 인라인 onclick에 사용자 문자열 넣지 말 것(`data-*` 사용).

## 3. 화면 명세 — 폰 (폭 1023px 이하)

공통 상단: 흰 바탕 헤더(뒤로 44px · 제목 · 우측 PC 상태 점 또는 ⋯). 새 채점 흐름 화면에는 **단계 막대** `1 정답지 · 2 답안지 · 3 결과` (4px 막대 3개, 현재 단계 코랄).

### 3-1. 홈 (= 채점 기록) — 지금의 "기록 선택 팝업 + 빈 홈" 대체
- 로그인 후 바로 이 화면. `_ssShowSessionPicker` 팝업과 `homeView`(ScoreSnap 열기 버튼) 제거.
- 코랄 헤더: "ScoreSnap" + 학원명 · 학원장, 우측 ⋯(로그아웃).
- 헤더 안 흰 카드: **PC 채점 프로그램 상태** (초록 점 "켜짐 · PC1 · 1분 전 확인 · 대기 N건" / 회색 점 "꺼져 있어요 — 학원 PC에서 start.bat 실행" ) → 7장 heartbeat 필요.
- 큰 카드 버튼 "새 시험 채점하기 / 정답지 1장 → 학생 답안지 여러 장".
- "최근 채점 기록 · 폰·PC 공유 · 5일 보관" 목록: 시험명, `N분 전 · M문항 · K명 채점 · 평균 X점`, 배지(`확인 N` 노랑 / `답안지 대기` 코랄 / `내일 삭제`). 행 전체 클릭 = 열기. 삭제는 상세(결과 목록) ⋯ 메뉴로 이동.

### 3-2. 정답지 촬영 (`_renderAnswerKeyCapture`)
- 시험지 형태: 큰 선택 카드 2개 [번호형 / 번호 한 줄에 문제 하나, 단어|뜻 목록 포함] [표 형식 / 한 줄에 칸 여러 개]. 기본 번호형. "잘 모르겠으면 AI가 자동으로 판단" 텍스트 링크 = `auto`.
- 가운데 점선 안내 영역: "정답이 적힌 시험지 1장", [답지 보기] 인쇄 권장, "PC: 프리뷰 [화면 복사] 후 Ctrl+V".
- 하단 액션바: [앨범] (보조) + [정답지 촬영] (주).
- 정밀 모드 배지는 이 화면에서 뺀다(검토 화면 ⋯ 메뉴 "정밀하게 다시 읽기"로만).
- 분석 중 화면 문구: "학원 PC가 정답지를 읽고 있어요 · 보통 30초~1분" (기존 "5~10초" 문구 삭제).

### 3-3. 정답지 검토 (`_renderAnswerKeyReview`)
- 위: 정답지 썸네일(누르면 사진 보기) + **시험 이름 입력칸**(바로 수정) + "번호형 · 43문항 인식".
- 탭: [전체 43] [확인 필요 3]. 확인 필요 = `confidence < 0.8` 또는 정답 빈칸. 확인 필요가 있으면 그 탭이 기본.
- 행: 번호 · 문제 · 상태 배지(흐림 / 정답 없음) · 정답 입력칸(높이 40px). **정답 수정 시 전체 재렌더 금지** — 그 행 배지만 갱신(스크롤 유지).
- conf 퍼센트 숫자 표시는 없앤다.
- ⋯ 메뉴: 정답지 사진 보기 / 다시 촬영 / 정밀하게 다시 읽기.
- 하단: [정답지 확정하고 답안지 찍기 ›] + 안내 "확정하면 다른 기기에서도 이 정답지로 이어서 채점할 수 있어요".

### 3-4. 답안지 추가 + 채점 진행 (`_renderStudentCapture` + `_renderBatchProgress` 통합)
- **전체 화면 스피너(`_renderBatchProgress`) 폐기.** 이 화면에 머문 채로 진행 표시.
- 상단 카드: "8장 중 3장 채점 완료 · 약 3분 남음" + 진행 막대 + "학원 PC가 한 장씩 차례로 채점해요. 화면을 닫아도 계속되고, 끝나면 결과 목록에 들어가요."
  - 남은 시간 = (남은 장수) × (최근 완료 건 평균 소요 시간). 완료 0건이면 "계산 중".
- 사진 그리드(3열): 사진 + 번호 + 아래 상태 — 완료(이름·`40/43`), 채점 중…, 대기(`N번째 차례`), 실패(다시 시도). 대기 중인 사진만 ✕ 삭제 가능.
- 하단: [앨범에서 여러 장] [한 장 더 찍기]. 사진을 추가하면 **자동으로 채점 요청**(별도 "일괄 채점" 버튼 없음).
- 모두 끝나면 결과 목록으로 가는 버튼이 하단 주 버튼으로 바뀜: [결과 보기 (8명) ›].

### 3-5. 결과 목록 (`_renderResultGrid`)
- 헤더: ‹ 홈 · 시험명 / `43문항 · 20분 전 · 서버 저장됨` · ↻ · ⋯.
  - ⋯ 메뉴: 정답 목록 / 정답지 사진 / 정답지 다시 올리기 / 이 기록 삭제. (지금 헤더의 버튼 8개를 여기로)

- 정렬 칩: 찍은 순서 / 점수 낮은 순 / 이름순.
- **카드 그리드 → 한 줄 목록**: 번호 · 이름(미인식이면 "이름을 입력해 주세요") · 배지(`확인 N문항`, `이름 미인식`) · 오른쪽 점수(색) + `31/43`. 실패 행은 빨간 바탕 "채점 실패 · 눌러서 다시 채점".

### 3-6. 학생 상세 (`_ssOpenStudentDetail` / `_buildStudentDetailHtml`)
- 헤더: ‹ 결과 목록 · [‹] `2 / 12` [›].

- 세그먼트 탭: [틀림 12] [확인 2] [맞음 29]. (지금의 그룹 헤더 + 접힘 details 대체)

## 5. 시험 형식별 상세 표시 (폰·PC 공통, 자동 전환)

시험(기록) 단위로 한 번 판단해 `_state.viewMode`에 둔다. 상세 화면 위에 작은 [보기 방식] 선택(자동/기본/영영/표)으로 수동 변경 가능.

```js
function _ssDetectViewMode(key) {
  if (key.layout === 'table') return 'table';
  const qs = key.questions || [];
  const isEnWord = s => /^[A-Za-z][A-Za-z' .\-]*$/.test(String(s || '').trim());
  const enAnswers = qs.filter(q => isEnWord(q.answer)).length;
  const longEnStems = qs.filter(q => /[A-Za-z]/.test(q.stem) && String(q.stem).trim().split(/\s+/).length >= 5).length;
  if (qs.length && enAnswers / qs.length >= 0.7 && longEnStems / qs.length >= 0.6) return 'ee';
  return 'basic';
}
```

- **basic (단어 → 뜻)**: 지금과 같은 한 줄. 번호 · 문제(굵게) · 학생 답(틀리면 빨강 취소선) · `정답 …`(초록) · 애매 배지 · ✓/✗.
- **ee (영영: 긴 영어 설명 → 영어 단어)**:
  - 첫 줄: **정답 단어**(초록, 17px 굵게) ← 학생 답, 둘째 줄: 영어 설명(13px `--sub`, 줄바꿈 허용).
  - 학생 답은 정답과 글자 단위로 비교(편집거리 정렬)해 **다른 글자만 빨강 배경 + 밑줄**. 빈칸은 회색 "(빈칸)".
  - 배지: 편집거리 ≤2 이고 길이 4 이상이면 `철자 비슷`, 정답과 앞부분 5글자 이상 같고 끝만 다르면(patient/patience) `품사 다름`. 판정은 바꾸지 않고 표시만.
- **table (표 형식)**: 시험지와 같은 표 모양.
  - stem 형식 `"leave [과거]"`를 파싱해 주어진 단어(`givenColumn` 값)별로 묶는다: `/^(.*)\s\[(.+)\]$/`.
  - PC: 열 = 번호 · 주어진 단어 · `answerColumns` 각 열. 칸 = 학생 답 + 아래 작은 글씨(맞음 / `정답 …` / `확인 · …`). 틀림 빨강 칸, 확인 노랑 칸. **칸 클릭 = 정답↔오답 토글**.
  - 폰: 줄(주어진 단어) 하나 = 카드 하나, 안에 answerColumns 칸을 가로로.
  - 기본 탭 "틀림·확인 줄만 (N줄)", 전체 보기 탭. 점수는 `맞은 칸 / 전체 칸`.
- 마킹 사진은 형식과 무관하게 기존 V 표시 로직 그대로.

## 7. PC 채점 프로그램 상태 표시 (heartbeat)

- `worker.js`가 시작 시 + 60초마다 상태를 기록: 문서 예 `scoresnapSessions/worker_{academyId}_{WORKER}` = `{ academyId, kind:'worker', workerName, lastSeen: serverTimestamp(), busy: bool, version }`.
  - 같은 컬렉션을 쓰면 기존 Rules로 통과할 가능성이 높다 — **먼저 firestore.rules 확인**. 안 되면 별도 컬렉션 + 규칙 추가.
  - `store.listSessions()`·worker `pump()`에서 `kind === 'worker'` 문서는 **반드시 제외**(목록·작업 처리에 섞이지 않게). 5일 만료 정리 대상에서도 제외.
- 앱: 홈/헤더에서 `onSnapshot`으로 구독. `lastSeen` 2분 이내 = 켜짐(초록), 그 이상 = 꺼짐(회색) + 안내 문구. 대기 작업 수는 `kind:'job', status:'queued'` 개수.
- 기존 `index.html`의 15초 후 상단 배너는, 꺼짐 상태일 때만 답안지 화면 진행 카드 안에 안내로 표시하는 방식으로 대체.

## 8. 작업 순서 (단계마다 배포 가능하게)

1. **기반**: CSS 변수·클래스, SVG 아이콘 세트, 헤더/하단 액션바/탭/칩/행 공용 함수. 라이트 테마 전환. (기능 변화 없음)
2. **폰 흐름**: 3-1 홈(팝업·빈 홈 제거) → 3-2/3-3 정답지 → 3-4 답안지+진행(스피너 폐기, 자동 채점 요청) → 3-5 결과 목록 → 3-6 상세(basic만) → 3-7 마킹 사진 보기.
3. **형식별 상세**: 5장 `ee`, `table` + [보기 방식] 선택.
4. **PC 레이아웃**: 4-1 3칸(1024px 이상), 키보드, 사진 확대·전체 화면(4-4), 4-2 정답지 검토 PC.
5. **카톡 연속 전송**: 4-3 + `kakaoSentAt`.
6. **heartbeat + QR 바로 열기**: 7장, 6장 마지막 줄.
